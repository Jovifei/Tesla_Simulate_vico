# v1.4 independent research contracts (M0)

Source: Issue #44 and approved PR #43 at `8df352adf715705ba98536c77c8d94c5ac9424f4`. This directory does not modify or activate product audio. Registry v1.0 records the nine explicitly named first-round identities and ten *planned* route/package identities. A vehicle with an unresolved template mapping has `catalog_status: null`: it is a draft identity, not a new formal status or a `TARGET_LOCKED` vehicle. Only mappings specifically established by the approved source are filled; `TARGET_LOCKED` requires a non-null template. The 11 later targets are not invented. Legacy keys are historic App bank selectors, not OEM engine specifications. RX-7 is blocked `MODEL_INCOMPLETE`; the other entries are `SPEC_UNVERIFIED`.

`vehicle-registry.schema.json` describes interchange shape. `contract.validate_registry` enforces further semantic checks, including unique vehicle and non-null legacy keys and complete package-bound audition records. `contract.playable` defaults to false and requires the caller to independently authenticate the owner audition for the exact route, package and actual SHA-256. This project does not currently implement an owner-signature verifier. JSON claiming `PASS`, an evidence path, or a manually supplied boolean alone is not proof of that authentication. Product callers must fail closed until such a verifier exists, verify the actual bytes, and keep device/cabin/vehicle gates distinct.

The frozen T1–T4 declared authoritative paths and hashes were not located in the scoped source material. `check-frozen` without arguments returns BLOCKED (exit 2). When a future caller supplies all of `--root`, `--manifest`, `--manifest-sha256` and `--source-commit`, it verifies the exact pinned manifest bytes, checks its source_commit matches the separately supplied 40-hex commit, and reads the four distinct safe in-root files to verify each digest. The manifest format is `{"schema_version":"1.0","source_commit":"<40 lowercase hex>","files":{"T1":{"path":"<relative file>","sha256":"<64 lowercase hex>"},"T2":{...},"T3":{...},"T4":{...}}}`. Missing, malformed, unsafe or mismatched data do not pass. A match reports `VERIFIED_PINSET` and exit 0 **only for the caller-supplied pinset**; the manifest's claimed source commit and the pin's authority are not independently authenticated here. A synthetic fixture is not an official baseline. Never use this command to regenerate or overwrite trajectories.

`generate` accepts only explicit C0, C0_<vehicleId>, H_<vehicleId> prescriptions and creates a new file at `<output_root>/generated/<scenario_id>/scenario_config.json` using exclusive creation. It does not supply an approved recipe, interpolate, simulate, render, calibrate, or claim any OEM truth. The caller supplies every point. Issue #44 specifies four controls: throttle, RPM, load, and gear. Candidate interchange fields are `throttle` (normalized [0,1]), `rpm` (rev/min), `load` (normalized [0,1]), and `gear` (integer ordinal). Neutral and reverse encoding and gear range are **unknown**, and integers must not be interpreted as an approved drivetrain mapping. `time_s` is point metadata, not a fifth control; acceleration is not a v1.4 control. Units, scaling, and gear semantics remain candidate conventions pending recovery of the referenced first-round authoritative specification. The generator checks finite numbers, ranges where specified by this draft, increasing time starting at zero, and start-mode compatibility. `START_COLD` is in `scenario_config`, separately from the four inputs. The JSON Schema describes structure; runtime validation also enforces ordering and start mode.

Examples from the repository root (Python 3.10+; no installed third-party libraries):

```powershell
python tools/sound_sim/v14_contract/contract.py check-registry
python tools/sound_sim/v14_contract/contract.py check-frozen
python tools/sound_sim/v14_contract/contract.py matrix
python tools/sound_sim/v14_contract/contract.py generate <explicit-recipe.json> <new-output-root>
python -m unittest discover -s tools/sound_sim/v14_contract -p 'test_*.py' -v
```

`matrix` is a plan projection only: 40 hot and 10 cold cases are `NOT_RUN`; H cases are counted separately. It is not capture, human, acoustic, or vehicle evidence. These independent Python tests use synthetic fixtures; they do not run the real engine, Simulink, Android, a device, or listening validation.
