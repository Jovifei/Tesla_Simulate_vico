# APP-2 车内声浪 App 候选交接（2026-09-27）

状态：`LOCAL_ANDROID_CANDIDATE`。在 APP-1 独立 `:player` 上完成首批车内输入和持续播放能力。此状态不是实车验收、完整车型移植或产品发布。

## 目标与复用结论

目标是把 Android 手机固定在车内，按车速和纵向加速度实时合成声浪，并可切换车型。

- 旧参考工程：`docs/reference/tesla-engine-sound-main`。保留其界面和 BLE/OBD 设计供研究；其 Kotlin 未调用 JNI，Gradle/CMake 未接通 native 引擎，本轮没有把它判定为可运行的声音 App。
- `android_vehicle_sound_demo/app` 是 PC WebSocket 控制器。
- 当前底座为 `android_vehicle_sound_demo/player`，JNI/Oboe 实时核心和两个合成实验 profile 已存在。

## 本轮实现

- `MotionEstimator.java`：车头方向四选一；借重力向量投影线性加速度并拒绝竖直轴；GNSS 速度精度需可用且不大于 5m/s；GNSS 最长 2s、IMU 最长 250ms、重力最长 2s；IMU 积分速度相对最近 GNSS 速度限制在 ±3m/s；无效输入交给核心安全回退。
- `DriveAudioService.java`：管理 Replay/GNSS+IMU、JNI 生命周期和单一命令线程；声明 location/mediaPlayback 前台服务，接受用户可见界面发起的会话；处理音频焦点丢失、系统输出断开、蓝牙设备移除和 Oboe 错误；通知栏可停止。
- `PlayerActivity.java`：保留两个实验 profile 切换，增加车头方向选择、音量滑条、速度/输入质量、回放和停止；失效速度显示不可用，不伪报为 0。
- `native_player.cpp`、`volume_ramp.hpp`：音量作为有界队列命令在 Oboe 音频线程平滑应用；错误状态通过 atomic 发布，未在实时回调调用 JNI。
- Manifest 和中英文资源声明服务权限及会话状态。
